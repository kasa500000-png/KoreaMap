## 아키텍처 방향

- 공통 코어는 좌표, 카메라, 피처, 이벤트, 오류 및 어댑터 계약을 정의한다. 백엔드 클라이언트를 필수 의존성으로 두지 않는다.
- Web과 React Native 구현은 공통 모델/API를 최대한 공유한다. 플랫폼별 차이와 지원하지 않는 기능은 명시한다.
- MapLibre 스타일 명세에 기반해 사용자 지정 스타일을 지원한다. 렌더러별 지원 범위를 확인하고 호환성을 테스트한다.
- 한국 좌표계 변환, 한국어 표기, 주소·검색 모델은 실제 데이터 요구사항을 조사한 뒤 결정한다. 좌표 축 순서와 단위를 문서화한다.
- SDK 코드, 데이터, 외부 에셋의 배포 경계를 구분한다. 자체 호스팅에 필요한 데이터 및 에셋의 재배포 조건도 확인한다.

## 1단계 조사 출발점

다음 URL은 확인할 공식 출처 목록이다. 이번 문서 작성 단계에서 최신 내용·릴리스·라이선스를 검증했다는 뜻이 아니다.

버전은 이 단계에서 임의로 지정하지 않는다. 1단계에서 공식 릴리스 및 플랫폼 간 호환성을 확인하고 2단계 설치 전에 고정한다. 한국 공공데이터는 개별 데이터셋의 이용조건을 확인해야 하며 포털 등록 자체를 이용허락으로 간주하지 않는다.

## 단계별 검증과 승인

각 단계는 변경 범위에 맞는 테스트와 QA 결과를 기록한 뒤 완료 처리한다. 실행 환경이 없는 검증은 미검증으로 남기고 해당 플랫폼의 완료를 선언하지 않는다. 후속 단계의 독립 작업은 진행할 수 있지만 선행 검증이 필요한 릴리스는 진행할 수 없다.

가능하면 단계별 브랜치와 PR로 검토한다. GitHub 원격 주소와 권한이 없으면 로컬 브랜치·커밋을 만들고 PR을 차단 사항으로 기록한다. main 병합·운영 배포·공개 저장소 전환·npm 실제 발행은 각각 명시적 승인 이후에만 수행한다.
