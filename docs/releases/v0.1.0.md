# v0.1.0 릴리스 후보 최종 점검

확인일: 2026-10-19. **로컬 후보 준비 완료, 공개 발행 불가**. 기능·패키지 검증과 배포 승인을 분리한다. npm high 취약점 2건과 아래 미검증/승인 항목은 해결되지 않았다.

GitHub 커넥터로 확인한 저장소는 이미 Public이며 기본 브랜치는 `chore/project-policy`다. 새 후보는 로컬 `release/v0.1.0-preparation`에만 준비했다. 공개 push/PR, main merge, visibility 변경, npm publish, tag, GitHub Release, 운영 배포를 수행하지 않았다.

## 1. 구현한 릴리스 준비

- 5개 SDK의 후보 이름을 `korea-map-core`, `korea-map-web`, `korea-map-native`, `korea-map-styles`, `korea-map-data-adapters`로 통일했다. 2026-10-19 공개 registry 조회가 모두 404였으며 예약·소유권·최초 발행 성공을 의미하지 않는다. `npm whoami`는 ENEEDAUTH였다.
- MIT LICENSE를 유지하고 영문/국문 진입 문서, 기여·행동·보안 정책, 데이터/의존성 고지, Issue/PR 템플릿을 준비했다. MapLibre style spec은 실제 설치 metadata의 ISC로 확인했다.
- 초기 pending Changeset 11개를 기존 version 0.1.0의 CHANGELOG에 통합했다. 빈 initial-release-baseline Changeset은 추가 버전 증가를 요청하지 않는다. 이후 변경에는 정상 fixed-group Changeset을 사용한다.
- manual-only npm workflow는 `NPM_PUBLISH_ENABLED`와 정확한 `NPM_APPROVED_COMMIT` 일치, `npm-release` environment, 재빌드/감사/무결성 검사를 요구한다. 기본 비활성화이며 OIDC/보호 환경을 실제로 설정하거나 발행하지 않았다. 자동 GitHub Release/배포는 없다.
- `release:prepare`는 실제 5개 tarball의 SHA-256/SHA-512 SRI와 소스 커밋/dirty 상태, CHANGELOG 기반 RELEASE_NOTES.md를 ignored `artifacts/release/`에 생성한다. dirty tree, 누락 승인, 다른 커밋, 패키지 누락, 파일 변조는 검증에서 거부한다. 체크섬은 서명/provenance가 아니다.

## 5. 라이선스·보안·비용

- SDK/합성 fixture MIT와 데이터/폰트/아이콘/상위 라이브러리 조건을 분리했다. 실제 공공데이터·OSM·폰트 파일·개인 위치 기록을 새 Git/npm payload에 포함하지 않았다.
- 작업 트리/index/로컬 ref의 Git 이력/실제 tarball 정적 검사에서 발견 0을 확인했다. 이는 휴리스틱 범위이며 원격 전용 이력·위장 비밀·권리 보증·계정 청구 설정까지 인증하지 않는다.
- 실제 Web 정적 출력과 Android/iOS JS export 94파일에 기존 규칙을 적용하면 외부 URL 후보 120, URL credential 후보 1, 이름 기반 후보 4가 나온다. 후보가 포함된 파일들은 이전 수동 검토본과 바이트 동일함을 확인했다(94파일 중 46개 동일; 변경 48파일의 후보 0). URL parser probe, RN password 의미 토큰, 문서/namespace와 Expo Go 조건부 asset CDN을 구분했으며 실제 secret 패턴 일치는 없다. Native OS egress를 통과로 주장하지 않는다.
- high node-forge 1.4.0 / GHSA-86w9-cpqp-85rv, braces 3.0.3 / GHSA-vfj7-8cjw-p6xm은 audit metadata에서 patched_versions=null이다. 안전한 수정 버전이나 검증된 대체 그래프 없이 강제 override·감사 예외를 추가하지 않았다.
- 신규 제작자 Provider/공유 키/서버/유료 계정 연결이 없다. registry 의존성 설치와 운영자 자체 서비스 비용은 SDK 배포 비용과 구분한다. 표준 runner만 사용하며 cache/artifact 업로드/cron/유료 빌드를 추가하지 않았다. 발행 job에만 OIDC id-token:write를 선언했으며 실제 실행하지 않았다.

| 항목 | 판정 |
| --- | --- |
| 1. 외부 키 없이 SDK 빌드 | 통과 |
| 2. 독립 데모 실행 방법 | 통과: 후보 체크아웃에서 로컬 합성 Next.js 데모 |

| 4. 유료 API 가입 강제 없음 | 통과: fixture와 명시적 operator provider |
| 5. 라이선스/출처 적합 | 소스/패키지·Web 검증 통과; 최종 Native binary notices는 미완료 |
| 6. 플랫폼 지원 상태 명시 | 통과: Web 검증 범위 및 Native experimental/미검증 명시 |
| 7. 비공개 자료 없음 | 정적·tarball 감사 범위에서 발견 없음; 절대적 부재 보증 아님 |
| 8. npm 실제 설치 | core npm 로컬 tarball / Web 4개 pnpm 소비 설치 통과; **registry 및 Native 독립 설치 미검증** |
| 9. 문서와 구현 일치 | 링크·strict 예제·Next/Expo JS 빌드 검사 통과; 명시한 지원 한계 유지 |
| 10. 승인 전 공개/발행 금지 | 준수: 새 원격 쓰기·visibility 변경·publish·Release 없음 |

전체 공개 판정은 **차단**이다. high 2건, npm 계정·이름 소유권·최초 발행/보호 환경/OIDC, Native 실기기/iOS·glyph/PMTiles·binary notices, 안전한 비공개 보안/행동 신고 경로, 기본 브랜치 통합 승인과 발행 후 registry 설치를 해결해야 한다. 일부 기능을 제외한 experimental 공개를 원한다면 그 범위와 미검증 한계도 별도로 검토·승인해야 하며, 현재 high 감사 실패를 통과로 바꾸지 않는다.

GitHub 커넥터로 private vulnerability reporting 및 environments 설정 조회도 시도했으나, 해당 URL이 허용된 repository/search endpoint가 아니라는 HTTP 400을 받았다. 따라서 보호 환경·비공개 신고 활성화 상태를 확인한 것으로 처리하지 않았다.

로컬 브랜치 `release/v0.1.0-preparation`. 기반 QA 커밋은 `21a2c761795c29598e8ddfb468f81f31b0eecc73`이다. 후보 커밋 식별: `git log -1 --format='%H %s' release/v0.1.0-preparation`. 자기 커밋 해시는 커밋 후 사용자 보고와 clean source로 다시 생성한 ignored integrity.json에 제공한다. 공개 PR은 만들지 않았다.

## 8. 다음 단계

차단 사항 수정과 추가 검증은 진행 가능하다. 현재 후보의 공개 업로드·npm 발행·GitHub Release는 진행하지 않는다. 사용자 승인만으로 미검증 항목이 통과가 되는 것은 아니다. [릴리스 절차](process.md)에 따라 해결된 증거와 정확한 커밋을 검토한 뒤 각각 명시적 승인을 받는다. 실제 registry 설치는 발행 후 수행해야 하므로 사전 완료로 표시하지 않는다.
