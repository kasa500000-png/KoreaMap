# 데이터 라이선스와 공개 배포 정책

확인일: 2026-10-19. 개별 범위와 근거는 [데이터 원장](../data/sources.json), 사람이 읽는 보고서는 [공급원 조사](data-sources.md), 표시 지침은 [출처 표시](attribution.md)에 있다. 기관 이름이나 API 제공 방식은 라이선스가 아니다.

## 판정 기준

| 등급 | 필요한 근거 | 허용 경로 |
| --- | --- | --- |
| A | 정확한 데이터/필드 범위에 상업·저장·수정·재배포 권한과 조건 확인 | 운영자 opt-in 후 수집 후보; 취득한 파일은 별도 품질·출처 검사 |
| B | API 사용과 저장/재배포 제한이 명시된 현행 조건 | 운영자 설정 기반 외부 API 어댑터만; 수집·오프라인 DB 배포 금지 |
| C | 약관 열람 실패, 허가 범위 모호, 공급약정·권리자 등 미확인 | 기본 및 선택형 실행에서 제외; 증거 보완 후 새 검토 |
| D | 특정 용도 금지 또는 자유로운 SDK 배포 목적과 불일치 | 해당 용도 제외 |

현재 B는 0개다. API로 받는 TourAPI 구조화 정보는 그 이유만으로 B가 되지 않는다. 반대로 저장 권한을 모르는 VWorld를 B로 처리해서도 안 된다. A의 좌표계가 unknown인 경우 권리 판정과 별개로 지도 적재를 보류한다. 좌표가 없는 산책로의 주소를 임의 좌표로 바꾸거나 공원 내 반려동물 시설 존재를 공원 전체 출입허가로 확대하지 않는다.

A 판정은 해당 공식 페이지의 권리 표시에 근거한다. 내려받지 않은 파일의 모든 셀·이미지·개인정보까지 검사했다는 뜻이 아니다. 수집기는 승인 필드만 추출하고, 예기치 않은 매체·권리 문구·스키마 변경이 있으면 격리해야 한다. 원본 URL, 권리자, 기준일, 실제 취득 시각, 파일 SHA-256, 이용허락 버전, 가공 이력을 배치별로 기록한다. 본 단계는 수집기를 실행하거나 구현하지 않았다.

## MIT와의 관계

| 조건 | SDK 코드와 함께 사용 | 데이터에 적용할 조건 | 판단 |
| --- | --- | --- | --- |
| MIT 자체 코드·합성 fixture | 가능 | MIT 고지 | 현재 SDK 배포 대상 |
| OSM ODbL 1.0 | 독립 코드로 사용 가능 | OSM 표시, ODbL 고지, 파생 DB의 동일조건·접근 제공 등 | A, SDK 코드와 데이터 배포를 분리 |
| 개별 공공데이터의 이용허락범위 제한 없음 | 검토된 범위에서 가능 | 원문 권리 표시 보존, 출처/가공 이력 유지 | A; `LicenseRef-DataGo-Unrestricted`로 구분 |
| 공공누리 제1유형 | 해당 데이터에 실제 적용 확인 시 가능 | 출처 및 유형 조건 유지 | 기관 전체에 일괄 적용하지 않음 |
| 공공누리 비영리/변경금지 유형 | 상업·수정 가능한 일반 에셋 목표와 충돌 | 개별 사용 조건 유지 | 기본 SDK 데이터/에셋에서 제외 |
| API 서비스 이용약정 | 어댑터 코드의 MIT와 분리 | 승인 계정·키·쿼터·캐시·표시·호스팅 제한 | B 또는 C; 원본 데이터 권리와 별도 검토 |
| 알 수 없는 권리/제3자 미디어 | 승인 불가 | 별도 확인 | C/D |

`LicenseRef-*`는 이 저장소의 식별자이며 SPDX 표준 라이선스라고 주장하지 않는다. 포털의 “이용허락범위 제한 없음”을 CC0, 공공누리 1유형, MIT로 바꾸어 표시하지 않는다. 해당 개별 파일에 광범위한 이용을 허용한다는 제공기관 표시로 판단했다. 의무가 명시되지 않은 자료에도 추적 가능한 출처 표시는 프로젝트 정책으로 요구한다.

OSM은 [저작권 안내](https://www.openstreetmap.org/copyright) 및 [ODbL 원문](https://opendatacommons.org/licenses/odbl/1-0/)을 함께 적용한다. SDK MIT 라이선스는 OSM DB를 MIT로 재허가하지 않는다. DB 결합·주소 보정·도로망 가공이 파생 DB에 해당하는지 판단하고, 공공데이터와 결합할 때는 필드별 계보를 유지한다. 별도 테이블이라는 구현 사실만으로 Collective Database라고 확정하지 않는다. Produced Work(지도 화면 등)와 파생 DB 의무를 구분하며, 필요한 DB 접근 제공 방식까지 데이터 릴리스에 포함한다.

공공누리 조건은 데이터별 표기 확인이 우선이다. 이번에 공공누리 사이트의 유형 페이지는 열람 실패했으며, [TourAPI 공식 상세](https://www.data.go.kr/data/15101578/openapi.do)의 1/3유형 혼재 안내를 확인했다. 이미지 유형을 API 전체의 “제한 없음” 표시로 덮어쓰지 않는다. 공공누리 3유형 사진을 수정 가능한 공통 에셋에서 제외하며, 원문 이용 자체가 전면 금지라고 표현하지 않는다.

## 취득과 운영 조건

- OSM 공개 타일 서버의 대량 수집은 [타일 서비스 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 제외한다. 원본 OSM DB의 개방과 서비스 용량·캐시·접근 정책은 별개다.
- VWorld, NGII, 주소정보는 공급 약정·이용목적 심사·제품별 권리와 필요한 경우 국외 서비스 조건 확인 전 제외한다. 포털의 무료 표기나 일반 규정 표제가 그 확인을 대신하지 않는다.
- API 키·쿼터·사용 목적 승인은 이용자 소유다. 제작자 계정 fallback, 공용 proxy, 설치 시 데이터 취득, 정기 수집 Actions를 만들지 않는다. 클라이언트 bundle의 환경변수도 공개될 수 있다.
- 개인정보, 연락처, 주택 상세주소, 미디어 권리 및 반려동물 출입정책은 저작권과 별개다. 필요한 시설 속성만 수집하고 폐업·휴업·수정 정보를 반영한다. 대표자 이름·개인 연락처를 통째로 배포하지 않는다.
- 도로명주소/주차장/산책로 테이블은 길찾기 가능한 도로망을 보증하지 않는다. 지오코딩·연결성·일방통행·보행 접근 가능성·고도교차는 별도 검증한다.

## 실행되는 차단 규칙

`pnpm check:data`와 `pnpm test:data`는 Python 표준 라이브러리만 사용하며 외부 요청을 하지 않는다. `pnpm check` 및 기존 3개 OS CI에 포함한다.

1. 카탈로그 필수 필드, 중복 ID, 공식 출처 도메인, HTTPS, 키 없는 URL, 권리 상태, 근거 상태, 출처 문구, 기준일 구분을 검증한다. A 승격 시 정확한 원본의 열람 근거와 네 가지 권리가 필요하다. unknown 또는 접근 실패는 허가가 아니다.
2. 검토는 최대 90일 후 만료된다. 현재 만료일은 2027-01-17이며 그 이후 검사는 실패한다. 조건 변경을 확인하여 원장과 보고서를 갱신한다. 날짜만 연장해 통과시키지 않는다.
3. `select_source`는 명시적 source ID와 운영자 opt-in이 있어야 한다. collect는 A만, external-api는 A/B만 선택할 수 있다. 함수/CLI는 자격 검사일 뿐 요청·다운로드·API 키 탐색을 수행하지 않는다. C/D는 두 경로 모두 차단한다.
4. Git 추적 파일과 무시되지 않은 신규 파일에서 지도 DB·CSV·XML/RDF·줄 단위 JSON·GeoJSON·이미지·글꼴·아카이브 등 payload를 차단한다. 검토된 정확한 설정/조사 경로 외 JSON, 중첩 GeoJSON, 바이너리, 심볼릭 링크도 검사한다. `data/`에는 두 정책 JSON만 허용한다. `.gitignore`와 별개로 index 검사는 강제 추가된 파일도 거부한다.
5. [공개 검토 목록](../data/publication.json)은 SDK/예제/서비스 runtime source의 출처와 SHA-256을 고정한다. 코드 속에 데이터를 끼워 넣거나 새 runtime 파일을 추가하면 검토 목록 불일치로 실패한다. 변경할 때 diff의 출처와 권리를 사람이 확인한 다음 해당 해시를 갱신한다. 일괄 자동 승인 스크립트는 제공하지 않는다.
6. `pnpm pack:check`는 실제 다섯 npm tarball을 검사한다. 현재 검토된 TS 소스에 대응하는 JS/선언 파일, MIT LICENSE, README, 제한된 package manifest만 허용한다. 원치 않는 데이터/소스맵/중복 파일/링크/경로 이동을 차단하고, tarball 바이트를 빌드 산출물과 대조한다. 깨끗한 소스 빌드 후 실행한다.
7. 커밋 직전 `pnpm check:data --staged`로 index를 검사한다. CI도 이 명령을 실행한다. source 자체에는 A 데이터도 넣지 않으며 별도 운영자 데이터 릴리스 정책이 준비되기 전 제3자 payload 허용 목록은 비어 있다.

이 검사는 알려진 경로와 형식 및 검토 해시의 일관성을 검증한다. 코드·문서에 위장된 임의의 복제물이나 잘못된 사람의 권리 판단까지 자동 판별하지 못한다. 정책과 해시를 동시에 바꾸는 diff의 수동 검토가 필요하다. 역사상 삭제된 모든 데이터의 부재, 외부 저장소, 실제 provider 응답의 적법성은 이 검사 범위가 아니다. 기존 보안 감사는 로컬 refs의 이력을 별도로 검사한다. 브랜치 보호 설정은 이번 변경에서 검증·강제하지 않았다.

외부 데이터 릴리스를 시작하려면 별도 manifest·원본 파일 검증·표시·ODbL 제공 의무·국외 서비스 조건·비용 감사를 구체화해야 한다. 현재 SDK npm 발행 승인을 의미하지 않는다.
