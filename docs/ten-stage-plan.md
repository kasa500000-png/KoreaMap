# 우선순위별 10단계 실행

기준 소스: main `259d75e116a2de456f546c736014d50197774a4d`. 사용자는 남은 작업을 10단계로 나눠 각 단계의 commit/PR/반영과 배포까지 진행하도록 요청했다. Android 물리 기기 검증과 macOS/Xcode 기반 iOS 빌드·검증은 이번 작업에서 제외하며, 제외가 해당 플랫폼의 지원 수락을 의미하지 않는다.

## 실행 계약

- 각 단계는 독립 브랜치에서 검토 가능한 변경을 만들고, 필요한 검사 후 commit/PR을 생성해 일반 merge commit으로 main에 반영한다. GitHub의 보호 설정이나 실패 검사를 우회하지 않는다.
- 기존 전체 보안·상위 타입·실지도 성능 실패는 해결 전까지 그대로 보존한다. 단계에서 개선한 코드/검사 통과와 전체 기능·릴리스 수락을 구분한다. 외부 원본·도구·저장 공간·계정 권한이 없으면 실패/미검증/차단을 보고하고 가능한 독립 작업을 계속한다.
- 매 단계마다 [진행 기록](progress.md), [로드맵](roadmap.md), [비용 감사](cost-audit.md)를 갱신하고 구현·파일·테스트·실화면·권리/보안·잔여·Git·다음 단계의 8개 항목을 남긴다.
- API 키 없는 기본 SDK/합성 데모와 제작자 비용 0 기본 경로를 유지한다. 유료 인프라·공유 계정·원본 지도/font payload·개인 위치를 Git/npm에 추가하지 않는다.
- 배포 대상은 사용자에게 질문한 선택을 따른다. 대상이 지정되지 않으면 배포 가능한 정적 산출물과 검증 자료까지 준비하고 실제 외부 배포는 미실행으로 기록한다. npm 최초 발행은 소유권/보호 환경/보안·플랫폼 게이트를 충족해야 한다.

## 단계와 종료 조건

| 단계 | 우선순위 | 실행 범위 | 수락/차단 판단 |
| --- | --- | --- | --- |
| 01 | P0 | 공식 보안 수정 경로 재확인, 안전한 의존성 대응과 감사 근거 | 전체 audit high/critical 0이 보안 수락. 수정 경로가 없으면 근거를 보존하고 BLOCKED |
| 02 | P0 | Web NodeNext/RN 공개 선언과 독립 소비 개선 | 두 verifier의 전체 PASS 필요. Bundler/앱 코드 부분 성공은 별도 보존 |
| 03 | P1 | Linux Firefox/WebKit 및 반복 생명주기·메모리 QA | 실제 browser 실행·외부 요청·정리·오류 결과. 미설치/실행 실패는 NOT_RUN |
| 04 | P1 | 고정 지도 렌더링 병목 개선 | 실제 1,000개 점·같은 지도/프로토콜·frame p95 33ms 유지. 진단과 수락 측정 분리 |
| 05 | P1 | 독립 tarball Android APK·가능한 에뮬레이터 검증 | workspace alias 없는 현재 APK/실행 증거. 장비 부재·JS export를 실행 통과로 바꾸지 않음 |
| 06 | P1 | 허가된 실제 POI 취득→검증→ETL→DB→지도 | A 원본·기준일/SHA/CRS·실제 적재·출처 필요. 합성 검증을 실자료 수락으로 표시하지 않음 |
| 07 | P1 | 한국 검색·라우팅 정답 평가와 개선 | 독립 정답 표본·오류율·좌표/모드/통행 제약·취소/오류 회귀. 현장 안전·실시간 교통 보장 금지 |
| 08 | P1 | 해안선/전국 타일 자원·안전한 생성/복구 개선 | 개별 원본 권리·CRS·섬/이음새·실제 생성 필요. 디스크 게이트·기존 성공 세대 보존 |
| 09 | P1 | 5개 패키지 버전/Changesets·후보 무결성·운영 권한 점검 | 실제 clean SHA·tarball/SRI·문서·권리·비용·소비 결과와 계정/환경 설정 구분 |
| 10 | P1 | 최종 회귀·지정 배포 대상 반영·전체 결과 | 최종 SHA·PR/merge·외부 요청/데이터/비용·지원 범위. 실패한 게이트/실제 미배포를 명시 |

공식 보안/타입 조사, 브라우저 환경, 실제 원본 접근과 타일 자원은 독립적으로 조사한다. 소스 변경·전체 빌드·실제 성능 측정은 충돌하지 않도록 단계별로 통합한다. main 통합은 preview 소스 반영이며, 미해결 수락 항목을 완료로 처리하지 않는다.

기존 기능·결과는 [clone 검증](research/clone-validation.md), [보안/타입](research/security-types-validation.md), [성능](research/map-performance-validation.md), [실행 계획](execution-plan.md)을 따른다. 이 계획만으로 어떤 새 기능 검증이나 외부 배포가 실행된 것은 아니다.
